# Work Log — 2026-08-19

## Summary
- Integrated the Image-Optimizer pipeline with the fixed `SiteImage` model.
- Centralized image constants and validation helpers in `apps/core` while keeping the serializer upload flow focused on optimization metadata.
- Added responsive image variant generation and clearer upload error responses.

## Tasks
- Connected `lossless.py`, `lossy.py`, `optimizer.py`, and `variations.py` to shared constants and the `CompressionResult` contract.
- Updated `SiteImageSerializer` to validate uploads, preserve SVG/animated files when configured, save optimized bytes, and store `file_name`, `file_size`, `width`, and `height`.
- Added `ImageVariant` persistence and nested read-only variant response data for generated responsive images.
- Moved image type validation helpers into `apps/core/validators.py` and added regular, favicon, logo, thumbnail, and hero validator entry points.
- Added favicon responsive sizes and prevented missing image-type values from producing raw `KeyError` exceptions.
- Changed empty site-image uploads to return HTTP 400 with a readable `No image file was uploaded.` error.
- Updated legacy migration validator references to use the current named validators after removing the old `ImageValidator` dependency.

## Verification
- Django migrations were applied successfully in the current environment.
- Language-server diagnostics pass for the touched serializer, validator, model, constants, and optimization modules.

## Publish Versioning
- Added content-addressed snapshots for generated header, footer, and page JSON
	using SHA-256 hashes stored through `BlobStore`.
- Added `asset_hashes` to publish versions for editable site and page CSS files.
- Kept image files as references rather than duplicating image bytes; rollback
	restores image paths from the published JSON representation.
- Rollback restores site name, header/footer HTML, page metadata, page HTML, CSS,
	and image references, then republishes the restored content as a new version.
- Rollback now removes database pages absent from the selected historical version,
	keeping the page API consistent with restored assets.
- Added version deduplication and unpublished-change detection using content and
	asset hashes, with transactional site/version updates and row locking.
- Published JSON and blob snapshots now use two-space indentation and a trailing
	newline for readable files.

## Notes
- `SiteSerializer` and `PageSerializer` still need explicit integration with the shared optimizer for their direct `favicon`, `logo`, `thumbnail`, and `hero_image` fields if those uploads should be optimized outside the `SiteImage` endpoint.
