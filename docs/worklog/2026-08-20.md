# Work Log — 2026-08-20

## Summary
- Added server-side rendering for published sites from materialized JSON files.
- Modularized the publish and rollback workflows.
- Changed rollback to activate the selected historical version directly.
- Improved published asset paths, rollback file handling, and public URL behavior.

## Tasks
- Added `PublishedPageView` and public routes:
  - `/published/{site-slug}/`
  - `/published/{site-slug}/{page-slug}/`
- Added Django template rendering through `templates/published_site.html`.
- The renderer reads only `published/sites/{site-slug}/header.json`,
  `footer.json`, and page JSON files; it does not read draft database content.
- Kept published JSON asset references relative so content hashes remain stable
  across local, staging, production, S3, and CDN environments.
- Kept absolute URLs at the API boundary for publish responses and file fields.
- Split the publishing architecture into:
  - `PublishService`
  - `RollbackService`
  - `RestoreService`
  - `PublishContentService`
  - `PublishAssetService`
  - `PublishVersionService`
- Moved current published JSON output from the old assets path to:
  `published/sites/{site-slug}/`.
- Changed rollback to restore and activate the selected version directly rather
  than calling publish again and creating a new version.
- Added materialization of the selected version's JSON files during rollback.
- Fixed rollback restoration so existing header, footer, CSS, and page HTML paths
  are overwritten instead of creating collision-suffixed files.
- Added cleanup of HTML, CSS, and hero-image files when pages are deleted or
  removed during rollback.
- Fixed duplicate service method declarations and missing rollback asset-service
  wiring discovered during validation.
- Updated the publish versioning report and README with public rendering,
  versioning, rollback, and modular-service documentation.

## Verification
- Django system checks pass after the public rendering and service refactors.
- HTML minifier tests pass: 8 tests.
- Existing publish tests still contain assertions for the older publish response
  shape and need updating to the current structured snapshot response.

## Notes
- Published JSON is intentionally stored with relative paths.
- Public API responses may expose absolute URLs generated from the request.
- Historical image bytes are not duplicated; rollback restores image references,
  while editable CSS content is retained in the blob store.
